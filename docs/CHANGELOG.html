v0.40.0

2026-06-27

Added

  • Gold sheet follows the selected corridor. The gold/silver module is now "UAE vs <your selected country>" instead of always UAE vs India. Pick PKR and you see Pakistan's retail gold + silver; pick EGP and you see Egypt's — each with its own headline rate, 30-day trend sparklines, and high/low/avg stats in that country's local currency. Changed

v0.32.5

2026-05-15

Fixed

  • UAE gold history was being overwritten downstream of v0.32.4. The scraper successfully produced 30 history points (confirmed in smoke tests) but scrapers/run_all.py::_merge_uae_gold_history() then blindly replaced side["history"] with whatever the rolling cron-snapshot file held — which was just 2 entries from before the igold swap. Result: published rates.json had 30-day silver history but only 2-point gold history, even though both scrapers were working correctly. Fixed by seeding the rolling dict with scraper-provided history first, then layering the file-based rolling entries on top so the fresher scraper values win.

v0.32.4

2026-05-15

Changed

  • UAE gold now uses igold.ae as primary source (same provider that gives us UAE silver since v0.32.2). Khaleej Times is the fallback when igold is unreachable. KT only ships today's price (2-3 cron-snapshotted entries passing for "history"); igold ships 30 daily 24K gold prices in the same JSON shape the UI already consumes. User-visible effect: the gold/silver bottom sheet now shows a full 30-day UAE gold sparkline + populated 30-day stats + populated Recent-Days mini-table for the UAE column — same fix v0.32.2 did for silver, completing the "all four columns have history" outcome.
  • Karat handling: igold's API does not differentiate purity values in its output, so 24K comes from the API and 22K is derived as 24K × 22/24 = 91.67%. Source field labels the derivation: "igold.ae (Dubai bullion, 24K AED/gram; 22K derived)".

Fixed

  • Defensive scale normalisation for igold's data array. igold's endpoint occasionally returns the data array in milligram scale (silver ~0.009, gold ~0.5) while last_price is consistently gram-scale. Reproduces unpredictably depending on edge-cache state. New _normalise_igold_scale() detects the mismatch by ratio and multiplies by 1000 when needed, so the scraper stays on the igold primary regardless of cache state.

GoldHistorySheet.kt::ratesForCarat was forcing the UAE silver list to emptyList() when carat=Ag — a v0.23 hardcoded assumption that "UAE silver has no history, ever". v0.32.2 made that assumption obsolete but the UI hadn't been told. Result: the JSON had 30 history points, the sheet still showed "spot only" placeholders.
  • Silver trend sparkline gate widened from indiaSilverChrono.size >= 2 to either side having data, so the row renders the UAE column too.
  • Trend header strings shortened from "Silver trend · India" to just "Silver trend" — the suffix made sense in v0.23, misleading now.
  • Empty-state message updated: "Silver history is India-only (UAE shows live spot)" → "Silver history is rebuilding — check back tomorrow", consistent with the gold variant. Only shows when BOTH UAE + India silver history are empty.

Internal

  • End-to-end bug from a stale client-side assumption vs updated server-side data. When changing a data source going forward, grep the client for emptyList<...>() next to that field name and confirm nothing's gated on the old "this is always empty" assumption.

v0.32.0

2026-05-15

Changed

Internal

v0.31.1

2026-05-15

Added

  • AutoSizeText composable — new reusable utility in ui/AutoSizeText.kt. Shrinks the font size in steps until the text fits the available width, then draws. Hits the TextOverflow.Ellipsis safety net only if even the minimum size doesn't fit.

Static font reduction would have hurt English; AutoSizeText hits the right size per locale. Applied at every label/chrome site app-wide: app title, MID-MARKET eyebrow, toolbar chips, gold-card header labels, sheet titles + subtitles, trend headers, stat headings, view-full CTA, history-table column headers, StatPill labels, CaratChip labels.
  • Numeric values and English-only unit codes (24K, 22K, 1g, 1kg, AED, ₹) stay as plain Text — their widths are predictable, no benefit from auto-sizing.

Changed

  • Replaced ~15 instances of maxLines = 1, softWrap = false, overflow = Ellipsis with AutoSizeText. Remaining softWrap = false sites are either numeric values or fixed-English unit codes.

v0.31.0

2026-05-14

Added

  • Share-best-rate button. New share icon in the top app bar composes a plain-text summary of today's BEST provider rate and fires Android's ACTION_SEND chooser so the user can forward it to WhatsApp / SMS / email / Telegram / anything else that accepts text.   • RateView composable now takes history: List<Double> so the trend arrow can compute the 7-day average without re-fetching; isDark / positive / negative palette decisions moved to outer scope so the trend arrow and the vs-mid line share one decision per card.

v0.30.8

2026-05-13

Fixed
