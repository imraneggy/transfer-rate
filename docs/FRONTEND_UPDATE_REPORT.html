Frontend improvement report

Transfer Rate UI Update · Step 1

This report records the first controlled frontend change: adding visible data-freshness protection to the Android home screen so users are warned before relying on delayed remittance rates.

1. Problem found

The repository copy of public/rates.json showed an old completed_at timestamp during the audit. A remittance comparison UI should not rely only on small relative-time text when feed age becomes operationally unsafe.

Risk

Users may assume values are current even when the scraper or Pages artifact is delayed.

Impact

Wrong timing can lead to poor transfer decisions, especially when AED→INR rates move quickly.

Fix

Add a prominent home-screen banner when feed age crosses defined thresholds.

3. Behaviour specification

Feed ageUI behaviour
< 3 hoursNo banner. Normal UI remains clean.
3–24 hoursDelayed warning: asks user to refresh.
>= 24 hoursCritical stale warning: tells user to confirm in the provider app before sending money.
Invalid timestampUnknown-age warning: asks user to refresh before relying on rates.

  • Confirmed the banner refresh button reuses the existing RatesViewModel.refresh() path instead of adding a second refresh mechanism.

5. Next recommended step

The next frontend improvement should be toolbar simplification: keep the home screen visually focused by moving secondary actions such as theme, share, about, and language into a menu while keeping refresh/freshness visible.
