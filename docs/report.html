1. Overview

transfer-rate is an Android 14+ app that displays the current 1 AED → INR exchange rate offered by major UAE remittance services (Wise, Remitly, LuLu Money, Aspora, Careem Pay) and tracks app-only services (e& Money, Botim Pay, Comera) for future inclusion. Rates refresh every 15 minutes.

The project's defining constraint is zero ongoing cost. No servers, no databases, no paid APIs. The data plane runs on GitHub Actions free tier; the publishing plane uses GitHub Pages; the app fetches a single JSON file over HTTPS.

Design thesis: a remittance comparison app does not need real-time tick data — providers reprice on the order of minutes to hours. A 15-minute scrape cadence on free infrastructure is operationally cheaper than a paid real-time pipeline and produces a result that is indistinguishable to the end user.

2. Tech stack

Data plane (Python)

  • Python 3.12 — language
  • httpx 0.27.2 — HTTP client (HTTP/2, sync & async)
  • beautifulsoup4 + lxml — HTML parsing where needed
  • concurrent.futures — parallel scraping (stdlib)
  • dataclasses — wire schema (stdlib)

Presentation plane (Android)

  • Kotlin 2.1.0
  • Jetpack Compose (BOM 2024.12)
  • Material 3 with Material You dynamic colour
  • Lifecycle ViewModel + StateFlow
  • OkHttp 4.12 — network
  • kotlinx.serialization 1.7.3 — strict JSON
  • kotlinx.coroutines 1.9 — concurrency

Build & CI

  • Gradle 8.11.1 with version catalog
  • Android Gradle Plugin 8.7.3
  • R8 full mode for release shrinking
  • GitHub Actions with SHA-pinned action references

Hosting & distribution

  • GitHub repo — code & data history
  • GitHub Actions — cron + deploy workers
  • GitHub Pages — JSON CDN
  • GitHub Releases or F-Droid for APK distribution

What is intentionally absent: no server-side runtime, no database, no analytics SDK, no crash reporter, no DI framework (Hilt/Koin), no Retrofit (overkill for one endpoint), no image loading library (no provider logos shown), no firebase/play services dependency. Every absent thing is a smaller attack surface.

The two planes are entirely decoupled. The contract between them is a single JSON file. Either side can be modified, redeployed, or swapped without affecting the other, as long as the schema version is honoured.

5. Scraper layer

Each provider is one Python file in scrapers/. They share a base class and produce Quote objects. The simplest is wise.py (uses a public JSON API); the most fragile are HTML scrapers that depend on a specific selector.

Provider table

ProviderStatusSource typeWhy this approach
WiseokPublic comparisons API Wise documents this for their marketing widget. Stable JSON.
RemitlyokPublic calculator JSON Used by Remitly's web calculator; anonymous quotes work.
LuLu MoneyokHTML (embedded JSON) Page embeds rate data in a script tag we extract by regex.
AsporaokHTML (data attribute) Landing page surfaces the AE→IN rate prominently.
Careem PayokHTML (embedded data) Marketing page renders rates client-side from injected JSON.
e& Moneyinvestigating— App-only. Stubbed pending stable public source.
Botim Payinvestigating— App-only. Reverse-engineering mobile API is fragile and ToS-sensitive.
Comerainvestigating— App-only. Same issue as Botim.

Anatomy of a scraper

Every concrete scraper subclasses BaseProvider and implements one method: 

class WiseProvider(BaseProvider):
    id = "wise"
    display_name = "Wise"
    API_URL = "https://api.wise.com/v3/comparisons/"

    def fetch_inr(self, amount_aed: float = 1000.0) -> Quote:
        with http_client() as c:
            r = c.get(self.API_URL, params={...})
            r.raise_for_status()
            data = r.json()
        # ... defensive extraction ...
        return Quote(provider_id=self.id, ..., status="ok",
                     fetched_at=self._now_iso())

The shared http_client() sets the User-Agent transfer-rate-bot/1.0 (+https://github.com/...), a 15-second timeout, and follow-redirects. Scrapers focus only on what to extract from the response; everything else is centralised.

6. Orchestrator

scrapers/run_all.py is the entry point of the data plane. Responsibilities:

  1. Run all 8 scrapers concurrently in a ThreadPoolExecutor.
  2. Catch every exception so one provider's failure cannot abort the run.
  3. Apply a 25-second hard per-provider timeout.
  4. If a provider failed this run but had a previous successful quote in rates.json, preserve the old value as status="stale" rather than show an error. This is the single most user-facing reliability behaviour.
  5. Sort results by the canonical PROVIDERS order so the JSON is deterministic.
  6. Write the output atomically: rates.json.tmp then os.replace(). Readers never see a half-written file.

7. GitHub Actions workflow

Two workflows, both security-hardened:

.github/workflows/scrape.yml

SettingWhy
permissions: {} at root Deny everything by default; grant contents: write only on the job that needs to commit.
Third-party actions pinned by full commit SHA Tags are mutable — an attacker who compromises an action's repo can re-point a tag to their malicious code. SHAs are immutable.
concurrency.cancel-in-progress: true If two cron triggers race, the older one is cancelled — no double-commits.
timeout-minutes: 5 Hard cap. A scraper that hangs cannot consume free-tier minutes.
No secrets: referenced Public data only. There is nothing to leak.

.github/workflows/pages.yml

Triggers on changes to public/ and republishes via the official Pages deploy action. Uses OIDC token (id-token: write) rather than a stored token.

9. Security posture

Network

  • android:usesCleartextTraffic="false" on the <application>.
  • Network Security Config restricts allowed domains to imraneggy.github.io only.
  • Strict TLS via OkHttp defaults; no custom trust manager.
  • No certificate pinning — GitHub Pages rotates certs frequently and a hard-pin would brick the app on rotation. Domain-allowlist is the stronger control here.
  • HTTP client refuses bodies > 1 MB.

App attack surface

  • Exactly one declared permission: INTERNET.
  • allowBackup="false"; explicit empty backup_rules.xml and data_extraction_rules.xml.
  • Single Activity with android:exported="true" only because Android requires this for LAUNCHER activities; no other exported components.
  • No content provider, no broadcast receiver, no service.
  • No custom URL schemes, no app links, no deep linking — nothing for another app to invoke.
  • R8 full-mode shrinks bytecode; android.util.Log.{v,d} calls are stripped in release.

Data parsing

  • Json { isLenient = false } — strict mode rejects malformed documents.
  • validate() caps amount, rate, fee to plausible ranges before showing them.
  • schema_version check refuses unknown future schemas.

Build pipeline

  • GitHub Actions: top-level permissions: {} denies everything; jobs grant what they need.
  • Third-party actions pinned by commit SHA.
  • Gradle wrapper distribution URL pinned with sha256.
  • Library versions pinned exactly in libs.versions.toml.
  • No keystore in the repo; signing config reads from environment.

10. Legal posture

Scraping

Scraping public marketing pages is generally permissible in major jurisdictions when done politely and against published material. We reinforce that with explicit choices:

  • Polite User-Agent identifying the bot, with a contact link.
  • One request per provider per scrape, every 15 minutes — well below any reasonable rate limit.
  • Only public marketing/rate pages are touched. We do not authenticate, replay private mobile APIs, or bypass paywalls.
  • TAKEDOWN.md documents a 24-hour removal process for any provider who requests it. This is what separates a responsible aggregator from a scraper-of-last-resort.

Trademark

  • Provider names used nominatively (i.e. to identify the source of the rate). No logos, no claims of affiliation.
  • Disclaimer in the app footer and in DISCLAIMER.md: "indicative rates, not financial advice, not affiliated."

Licensing

  • Code under MIT — maximum permissiveness, includes a no-warranty clause.
  • All dependencies are MIT/Apache-2.0/BSD compatible. No GPL.

Privacy

  • App collects nothing — see PRIVACY.md.
  • Play Store Data Safety form: declare "no data collected" truthfully.
  • Privacy policy URL = the rendered PRIVACY.md on GitHub.

11. Step-by-step build narrative

This is what was actually done, in order, when this scaffold was built. Use it as a reference if you want to rebuild from scratch or audit how pieces fit.

Step 1 — Repository skeleton
  1. Created the project directory, ran git init -b main.
  2. Wrote .gitignore with Python, Android, IDE, and OS exclusions.
  3. Wrote LICENSE (MIT) and requirements.txt with pinned versions of httpx, beautifulsoup4, lxml.
Step 2 — Scraper framework
  1. Created scrapers/base.py with the Quote dataclass and the BaseProvider abstract class. Decided every nullable field is genuinely Optional so partial data is acceptable.
  2. Created scrapers/utils.py with the shared http_client() factory carrying the polite User-Agent and timeout.
Step 3 — Wise reference scraper
  1. Implemented scrapers/wise.py against api.wise.com/v3/comparisons. This is the structural template all other scrapers follow.
  2. Defensive parsing: every field extraction is guarded; schema mismatch raises a RuntimeError with a descriptive message.
Step 4 — Other working scrapers
  1. Implemented Remitly (calculator JSON), LuLu (HTML embedded JSON), Aspora (HTML data attribute), Careem (HTML embedded data).
  2. For each, added a clearly-marked TODO/regex that may need tightening when run against real pages.
Step 5 — Stub providers (Botim, Comera, e&)
  1. Used BaseProvider._stub() to emit status="investigating" records with notes explaining why no scraper exists yet. Keeps these providers visible in the app so they're not forgotten.
Step 6 — Orchestrator
  1. Wrote scrapers/run_all.py running all scrapers concurrently with hard timeouts.
  2. Added the stale-tolerance behaviour (preserves last good rate when a run errors).
  3. Atomic write via temp-then-rename.
  4. Bootstrap public/rates.json committed so Pages can serve immediately even before the first scrape.
Step 7 — GitHub Actions workflows
  1. scrape.yml: cron */15 * * * *, runs python -m scrapers.run_all, commits if changed.
  2. pages.yml: deploys public/ on every change via the official Pages deploy action.
  3. Pinned all third-party actions by commit SHA. Top-level permissions: {}.
Step 8 — Android scaffold
  1. Set up Gradle: settings.gradle.kts, build.gradle.kts (root + app), gradle.properties, version catalog at gradle/libs.versions.toml, wrapper config with pinned sha256.
  2. AndroidManifest.xml: only INTERNET permission, cleartext disallowed, backup disabled, network security config wired.
  3. res/xml/network_security_config.xml: domain allowlist restricting connections to GitHub Pages.
  4. data/Rates.kt: serialisable data classes mirroring the JSON schema, with validate() applying bounds.
  5. data/RatesRepository.kt: OkHttp client with strict timeouts, body size cap, no-cache request.
  6. ui/RatesViewModel.kt: sealed RatesUiState (Loading / Ready / Failed); sort by effective rate within status group.
  7. ui/RatesScreen.kt: Compose Scaffold + LazyColumn; tap a card to open the provider URL in a browser intent.
  8. ui/theme/Theme.kt: Material 3 with Material You dynamic colour on Android 12+.
Step 9 — Documentation

12. Publishing checklist

Repository

  1. Create the public GitHub repo.
  2. git remote add origin … && git push -u origin main.
  3. Settings → Pages → Source: GitHub Actions.
  4. Add branch protection on main (require PR, require checks).

First successful scrape

  1. Trigger scrape workflow manually from the Actions tab.
  2. Verify https://<you>.github.io/transfer-rate/rates.json returns valid JSON with at least one status="ok" entry.
  3. Update RatesRepository.kt + network_security_config.xml if your username differs from the placeholder.

Android release

  1. Generate a 4096-bit RSA keystore. Back up to two locations.
  2. Set KEYSTORE_PASSWORD, KEY_ALIAS, KEY_PASSWORD in your build environment.
  3. ./gradlew :app:assembleRelease (or :app:bundleRelease for Play Store).
  4. Verify aapt dump badging app-release.apk reports sdkVersion:'34' targetSdkVersion:'34'.

Distribution

  1. GitHub Releases (free): tag a version, attach the signed APK.
  2. F-Droid (free): submit metadata YAML; F-Droid builds from source.
  3. Google Play ($25 one-time): bundle AAB, fill in Data Safety (declare "no data collected"), provide privacy policy URL.

14. Extending the project

Add a new provider

  1. Copy scrapers/wise.py to scrapers/<new>.py.
  2. Implement fetch_inr() for the new source.
  3. Add the class to PROVIDERS in run_all.py.
  4. Run locally: python -m scrapers.run_all && jq . public/rates.json.
  5. Confirm new entry has status="ok" and a sane rate.
  6. Open a PR; CI exercises it on merge.

Add a new currency corridor

Currently AED → INR. Adding AED → PHP, AED → PKR, etc. is mostly schema work: add quote to the JSON top level (already there), let scrapers accept a quote parameter, and parameterise the Android UI. The architecture supports it; the implementation hasn't been built yet because Phase 1 is INR-only.

Add fee transparency

The schema already includes fee_base and effective_rate. Some scrapers (Wise, Remitly) populate them; others leave fee as null. To extend: hit each provider's quote endpoint with the user's input amount, return the per-amount-tier fee. The app already displays effective rate when present.

Add historical charts

Each scrape commits a new rates.json to git. So git is the database. To build a chart: a sibling workflow can read the last N commits' JSONs and write a history.json for the app. No database needed.
